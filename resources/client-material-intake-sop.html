大家好，今天我们将梳理客户资料接收与锁定的标准作业程序。整体工作流共分十步，覆盖了从接收资料到最终交付的完整闭环。

黄金法则：先锁后写 / Golden Rule

规范做法：先鎖後寫

拿到客户资料后，必须通过建立清单、分层和数据锁定表来锁定事实，明确数据缺口，再规划写作逻辑。

✓ 确保源数据可追溯，减少后期由于版本或逻辑不一致导致的反复修改。

高危做法：立即起草

直接阅读后立即起草文档。这极易导致：

  • 混用过期版本数据
  • 解构数据之间的逻辑冲突
  • 在信息不全时盲目进行“合理推断”
“先锁后写”是保证合规与效率的基石。绝大多数返工都是因为起草阶段对数据来源不明确、直接从微信或邮件提取零散数字导致的。

1. 明确任务边界 / Identify Boundary

在开始任何实质性阅读前，首要任务是定位并锚定交付目标与合规管辖范围：

  • 项目基本信息：确认项目代号、适应症类别（如实体瘤/血液肿瘤）、当前临床开发阶段。
  • 目标文件类型：明确本次撰写的目标，如临床试验方案（Protocol）、研究者手册（IB）、研究报告（CSR）、知情同意书（ICF）等。
  • 监管管辖辖区：确认提交的监管机构，如NMPA、FDA、EMA或TGA，这直接决定了模板规范与合规检查标准。
  • 缺失信息标记：如有信息不全，必须使用标准占位符标记：
    [待确认：目标章节]      [待确认：最新数据截止日期]
首先，我们要确定监管管辖区，因为不同国家的申报指南有很大差异。如果目标不明确，要在第一时间采用[待确认]格式打上标记。

2. 建立资料清单 / Source Manifest

在提取数据前，对客户提供的所有文件建立结构化的源文件清单（Source Manifest），防范版本混乱：

ID 文件名 文件类型 版本与日期 覆盖内容 确切页码/定位 状态
SRC01 Protocol_v2.0_2026-06-07.pdf 临床试验方案 v2.0 (2026-06-07) 入排标准、主要终点 Section 4, Page 12 已锁定
SRC02 Safety_Data_Table_C3_v1.xlsx 临床安全性Excel v1.0 (2026-07-01) AE/SAE汇总数据 Sheet: Summary, B5:F20 已锁定
SRC03 Draft_IB_v0.5_CN.docx 草稿版研究者手册 v0.5 (2026-05-15) 非临床PK数据 Section 5.2, Page 45 待确认
注意：必须主动识别并标记重复文件、历史旧版本，以及文件名相似但内容不同的“疑似冲突文件”。
建立清单的好处是版本受控。我们必须准确记录每个文件来源 and 定位，甚至具体到Excel的单元格坐标。

3. 资料分层管理 / Data Stratification

写入监管文件的所有事实均需进行证据分层，拒绝来源模糊的混杂描述：

1. 申办方确认事实
(Sponsor-confirmed)
定义：客户直接提供并明确签字确认的临床数据、方案设计或统计结论。

处理：作为核心事实引用，但在引用时必须标注对应的 Source ID。
2. 外部证据
(External-evidence)
定义：公开发表的文献、指导原则、竞争品ClinicalTrials.gov登记信息或FDA/NMPA数据库记录。

处理：作为支持性背景或对照，必须在文后列出完整的参考文献或引文。
3. 逻辑推断
(Inference)
定义：基于不完整的数据，由AI助手或医学撰写员自行推算、建议或评估的结论。

处理：严禁直接作为事实写入。必须使用“建议/推测”表述并明确标记 `[待确认]` 供申办方决定。
这三层分级能够从根源上杜绝“数据幻觉”。逻辑推断绝对不能作为最终结论写入，必须由申办方签字盖章确认。

4. 建立数据锁定表 / Data Lock Table

针对以下关键数据，在起草前必须完成“数字 - 来源文件 - 确切位置”的硬性绑定：

  • 方案设计要素：样本量大小、给药剂量级别、给药周期与给药方案（Regimen）。
  • 试验核心逻辑：主要疗效终点（Primary Endpoints）、关键入选/排除标准（I/E Criteria）。
  • 安全性与PK：已发生的严重不良事件（SAE）、试验中止事件、关键PK/PD参数。
  • 时间与版本：数据截止日期（Data Cut-off Date）、方案版本号及发布日期。
绑定示例：
参数项数据值Source定位
样本量N = 45SRC01, Sec 9.1, p82
给药剂量10 mg/kgSRC01, Sec 5.3, p40
主要终点ORR (RECIST 1.1)SRC01, Sec 3.2, p24
数据锁定表是撰写过程的“数据真理库”。我们必须在动笔之前，把所有关键的量化指标和定位写进这张表里，避免在撰写时去反复翻找。

5. 缺口与冲突清单 / Gap Log

在核对资料时若发现逻辑或数据问题，切忌自行进行临床合理化或妥协处理。应立即登记在案：

冲突/缺口描述 风险等级 受影响章节 需客户确认/提供的事项 状态
Protocol宣称主要终点为PFS，但统计计划(SAP)表述为ORR 高风险 Protocol Sec 3.0 / CSR Sec 9.0 请确认以何者为准，并提供终版签字意见。 待解决
Excel源数据缺失 Cycle 3 安全性总结，仅有C1和C2 中风险 CSR Sec 12.0 / IB Sec 6.2 需补充提供 Cycle 3 的AE汇总统计文件。 待解决
引用的指导原则在今年6月已更新，旧版本依然被引用 低风险 Protocol 参考文献 建议将旧指导原则更新为最新发布版。 待解决
如果发现不同来源的文件之间有矛盾，我们一定不能做和事佬，不能替客户做选择，必须要详细列出清单，呈报给客户做最终决策。

6. 外部证据检索 / External Research

当数据存在事实缺口，或需要进行竞争性/背景研究时，应在锁定检索来源的前提下开展以下检索：

检索维度与数据源

  • 先例试验与方案设计：检索 ClinicalTrials.gov 等试验库，寻找同类靶点已上市或在研同类产品的试验设计和评价标准作为参考。
  • 监管指导原则与法规：从 FDA, EMA, NMPA (CDE) 检索最新的靶点特异性或疾病特异性研发指南。
  • 学术与安全性数据库：利用医学文献检索工具对背景机理、不良反应谱（如CRS, 神经毒性等）进行溯源。

合规存底要求：

外部检索获取的所有资料必须强制记录以下追溯信息：

  • 具体检索数据源与使用的关键词
  • 资料的版本/发布日期
  • 文章的唯一标识符（如 DOI / NCT 号）
  • 本方人员的检索与访问时间
做外部检索时，不要局限于搜索引擎。我们需要科学、规范地记录检索路径和访问日期，确保整个情报链条可以被追溯和验证。

一份监管文档的改动，会像多米诺骨牌一样影响其他文档。我们必须在动笔时就把联动的影响找出来，避免只改了Protocol却忘了更新ICF。

8. 结构化起草 / Structured Drafting

使用对应的专业文档标准撰写模板。在起草过程中，医学撰写员应时刻遵守：

客观中立原则 / Neutrality
使用客观、非人称、学术化第三人称叙述。不允许出现 “我们 (we)”、“我 (I)” 或带主观感情色彩的修饰性词汇。
避免口语化描述，例如将“这个药安全性很好”规范撰写为“截至数据截止日，受试者对本品的耐受性良好，未观察到DLT”。
一致性与严谨性 / Rigor
所有医学和统计术语在第一次出现时，必须使用全称 + 缩写。统一全文命名法（例如：RECIST 1.1, CTCAE v5.0）。
严禁夸大结论，不得把临床前或早期试验的推测性结论，写成已证实的普遍事实。
起草时必须使用规范的医学学术语言，坚决杜绝带有主观偏向的形容词。比如安全性好不好，要用数据和客观术语如“耐受性良好”来支撑。

  • 先双语，后单语：推荐在编辑和核对阶段保留双语对照版以进行数据稽查，在确认无误后再一键输出纯中文或纯英文的最终版。
翻译不仅仅是语言的切换，更是数据准确性的二次稽查。强烈建议在撰写和QC阶段保留双语版本，这样能非常容易地发现数字和逻辑翻译中的错漏。

10. 交付前三维质量控制 / Pre-delivery QC

文件正式交付给客户或监管机构前，必须在后台执行这三个维度的严格审查：

1. 引文核验 (Citation QC)
验证参考文献中所有 DOI、PMID、NCT 等身份标识符的真实性。

确保引用的学术结论和临床前数据与源文献的研究内容完全对应。
2. 单文档质量 (Intra-doc QC)
检查单份文档内前后数据的一致性。

例如：Protocol正文中的“安全分析集 N=40”与附录SOA表格、正文统计章节的数字必须完全匹配。
3. 跨文档一致性 (Cross-check)
开展跨文件对比（Cross-document Check）。

对 Protocol 与 IB、Protocol 与 ICF 之间的数据传递和名词统一进行最后一轮红队审查。
最后的QC阶段分为三维：引文核验、文件内部一致性检查和跨文档一致性检查。这三道防线能过滤掉大部分由版本更新滞后带来的数据硬伤。

核心自查问卷：四大终极发问

每一个最终写入文档的数据和结论，医学撰写员都应能明确回答这四个问题：

  1. 来源是什么？ (精确到哪份输入材料)
  2. 版本是什么？ (该材料的版本和日期是否最新)
  3. 定位在哪里？ (确切的文件页码、章节或Excel单元格)
  4. 是否已确认？ (申办方是否已签字，是否为未证实的推论)
在项目开展的最初，请使用这个标准的启动指令收集输入信息。在提交文件前，我们要拿这四个自查问题对关键数据逐一核实。
