客戶批注修訂指引

一致性控制、AI 輔助檢查與交付前 QC

適用：Protocol 版本修訂／客戶批注回應／跨章節一致性核對

HiRO Medical Writing Workflow｜2026-07-16

本簡報聚焦於收到客戶批注後的可追溯修訂流程。每項修改都要能回到批注、來源與受影響位置。
01｜目標

先控制變更，再開始寫字

可追溯

每項批注都有 Comment ID、處置決定、修改位置與回覆。

一致性

同一概念、數值、時間點與術語，跨章節維持單一表述。

可交付

完成修訂、AI 檢查、人工 QC、版本鎖定後再發送。

核心原則：批注是變更起點；核准來源與最終 QC 才是交付依據。
Protocol 修訂的風險通常來自局部修改造成的連鎖差異。流程的目的，是讓每個決定與每個受影響位置都留下證據。
02｜工作流

Comment-to-Change 全流程

1接收批注整理批注、版本、來源
2分類與分級內容／資料／格式／邏輯
3影響分析定位跨章節與跨文件影響
4修訂與回覆修改、記錄理由、形成回覆
5AI＋人工 QC檢查差異、確認證據、鎖定版本

建議工作順序：/plan → /draft → /audit → /refine → /cross-check

把批注處理視為一條可重複的工作流，而非單純的逐句改稿。先分清影響範圍，再執行修改。
03｜批注接收

先建立 Comment Log

欄位用途
[批注ID]全程唯一識別
來源／版本客戶文件、日期、Protocol 版本
位置Section、頁碼、段落、表格或 SOA
批注原文保留原始措辭與上下文
處置決定Accept／Partial／Clarify／Reject with rationale
狀態Open／In progress／Resolved／Pending confirmation

先問三件事

  1. 客戶想解決的是內容、表述還是證據？
  2. 此批注是否改變研究設計或執行要求？
  3. 哪些章節、表格、附錄需要同步？

資料缺口

以 [待確認：來源／數值／版本] 標記，保留後續追蹤。

Comment Log 是修訂的控制中心。位置資訊越精確，後續的交叉檢查與客戶回覆越可靠。
04｜分類

批注分類決定檢查深度

類型典型批注修訂動作建議檢查
內容／資料數值、劑量、樣本數、時間窗回到核准來源數值＋來源核對
邏輯／設計入排標準、終點、停藥規則做跨章節影響圖Protocol consistency
術語／語言縮寫、定義、語氣、翻譯更新術語表全文件搜尋
格式／版面表格、標題、交叉引用依模板修訂Word＋PDF 視覺 QC
證據／引用來源、文獻、法規依據核對原始文件引用與版本追蹤

判斷原則：會改變研究執行、受試者安全或主要分析的批注，進入 Major／Critical 影響分析。

分類不是行政動作，而是決定後續需要幾層驗證。邏輯、資料與安全相關批注，優先於語言和版面調整。
Section 02

影響分析

從一則批注，找出整份 Protocol 的變更邊界。

接下來從批注轉入影響分析。這一步用來避免只改到局部位置。
05｜影響分析

三層 Impact Map

Layer 1｜局部

同段／同表
句子、表格欄位、註腳、交叉引用。

例：將 Visit 4 改為 Visit 5。

Layer 2｜跨章節

設計與執行
Synopsis、Objectives、SOA、Procedures、Statistics。

例：新增一次影像評估。

Layer 3｜跨文件

整套提交文件
ICF、IB、SAP、eCRF、藥物管理文件。

例：修改風險或給藥規則。

輸出格式

Finding：批注 → 影響位置 → 修訂決定 → 需同步文件 → 責任人／狀態

影響分析至少要涵蓋同一文件內的章節、表格和附錄。若涉及風險、給藥或研究程序，應列出跨文件同步範圍。
06｜一致性

Protocol 一致性熱點

Synopsis ↔ 正文
目的、設計、樣本數、主要終點
Objectives ↔ Endpoints
每個目的都有對應測量與時間點
Eligibility ↔ Screening
入排標準與檢查項目完整對應
Treatment ↔ Dose rules
劑量、週期、減量、停藥邏輯一致
SOA ↔ Procedures
訪視、評估、抽血、影像、PK／PD
AE/SAE ↔ Safety
定義、分級、報告時限、特殊關注事件
Statistics ↔ Design
分析集、終點、樣本量、缺失資料
Appendices ↔ 正文
流程圖、決策表、評分標準與版本

高風險對照：SOA ↔ Footnotes ↔ Study Procedures；任何落差先升級審查。

SOA 是 Protocol 的中央控制表。任何訪視、評估、時間窗或條件性程序的變更，都要回查正文和註腳。
07｜修訂規則

建立 Single Source of Truth

先鎖定的元素

  • Protocol number／version／date
  • 研究藥物名稱與縮寫
  • Phase、研究設計、族群
  • 劑量單位、週期、訪視名稱
  • 主要／次要終點與評估標準
  • RECIST 1.1、CTCAE v5.0 等版本

修訂後同步

  • 全文搜尋舊值與同義表述
  • 回查表格、註腳、圖與附件
  • 回查 ICF、IB、SAP、eCRF
  • 更新目錄、頁碼與交叉引用
  • 以變更摘要說明理由與影響
  • 保留修訂前後版本證據

同一概念採同一術語；同一數值採同一單位；同一規則採同一邏輯。

一致性不是只看拼字。要建立術語、數值、時間點和版本的控制表，再用它驅動全文件搜尋與修訂。
Section 03

AI 輔助檢查

AI 做廣度與差異偵測；人員做證據判定與最終放行。

AI 的價值在於快速掃描大量文字與位置。最終判定仍需由熟悉研究與核准來源的人員完成。
08｜AI 架構

四層 AI 檢查法

A抽取擷取術語、數值、時間點、引用
B比對新舊版本、SOA 與正文、文件 A/B
C找矛盾定位差異、缺漏、條件衝突
D報告輸出 Finding、位置、嚴重度、建議

AI 輸出要有

原文片段｜位置｜差異類型｜影響範圍｜信心程度｜建議下一步

人工確認要有

核准來源｜醫學合理性｜法規適用性｜最終措辭｜Owner／Status

把 AI 任務拆成抽取、比對、矛盾偵測和報告四層，輸出會比直接問「請檢查全文」更穩定、更可追蹤。
09｜可複用 Prompt

AI 檢查 Prompt 模板

角色：Protocol QC Reviewer 任務：比較【修訂前】與【修訂後】，僅依據提供內容判斷。 檢查維度： 1. 數值、單位、劑量、樣本數、時間窗 2. 術語、縮寫、版本與定義 3. SOA、Footnote、Study Procedures 的對應 4. Objectives、Endpoints、Statistics 的邏輯連結 5. 交叉引用、表格、附錄與跨文件影響 輸出表格：ID｜Severity｜Location｜Evidence｜Difference｜XREF｜Recommended action｜Confidence 規則：資料缺口標示 [待確認]；每項 Finding 提供原文證據；未提供的資料列為 Open question。

建議輸入：先給 Comment Log＋變更摘要＋相關章節，再給全文或文件對照。

Prompt 的重點是限定資料範圍、指定檢查維度、要求位置與證據。這能降低泛化建議，讓 QC 人員快速複核。
10｜AI 應用場景

把 AI 放在高價值檢查點

任務AI 可協助人工重點
版本比較擷取所有文字／表格差異判斷變更是否符合批注意圖
術語一致性找出同義詞、縮寫與大小寫差異核准標準術語與首現定義
SOA 對照逐行比對訪視、評估、註腳確認執行流程與醫學合理性
交叉文件建立 Protocol ↔ ICF／IB／SAP 差異表確認受影響文件與變更責任人
格式檢查檢查標題階層、編號、引用完整性開啟 Word／PDF 做視覺確認

實務建議：AI Finding 先進入 QC Discrepancy Report，再由 reviewer 逐條標記 Resolved／Open。

AI 適合高量、規則化、位置明確的檢查。涉及臨床決策或法規判斷時，保留人工 reviewer 與核准來源。
11｜QC 分級

Finding 的嚴重度與處置

Severity判定特徵處置
CRITICAL可能影響受試者安全、研究執行、主要終點或核心數據修訂完成＋專家／客戶確認＋回歸檢查
MAJOR跨章節矛盾、關鍵程序缺漏、重要引用或邏輯落差修訂完成＋XREF＋二次 QC
MINOR局部術語、格式、語法或可讀性問題批次修訂＋抽樣確認
OBSERVATION改善建議或待客戶決策事項記錄於 Log，保留決策軌跡

Finding 格式：[ID]｜[Severity]｜[Location]｜[Evidence]｜[XREF]｜[Fix]｜[Status]

Severity 主要用來排序處理順序與決定是否需要升級確認。所有 Finding 都要有位置與證據。
12｜交付前 QC

Pre-delivery QC Gate

內容與一致性

批注 Log 全部有處置狀態
數值、單位、版本、日期完成核對
SOA、註腳、正文、附錄互相對應
Synopsis 與主要章節一致
入排標準與 Screening 評估一致

格式與證據

標題、編號、目錄、頁碼正確
表格、圖、註腳、交叉引用完整
Track Changes／Comments 已按交付要求處理
引用與版本可回溯至來源
Word 與 PDF 皆完成視覺抽查

Gate 判定：Ready for delivery／Requires revision／Pending confirmation

QC Gate 同時看內容和格式。即使內容已完成，頁碼、目錄、註腳和 PDF 轉檔仍需要獨立確認。
13｜客戶回覆

用 Response Matrix 讓回覆可追蹤

ID客戶批注處置修訂位置回覆文字
[C-001]Clarify visit windowAcceptedSection 7.1；SOA；Footnote b已依批注統一時間窗，並同步更新 SOA 與註腳。
[C-002]Confirm sample sizePendingSynopsis；Section 9.1待收到 [來源／統計決策] 後完成最終確認。
[C-003]Improve wordingAcceptedSection 4.2已依 Protocol 術語表修訂，並完成全文搜尋。

回覆原則：簡短說明 採納／部分採納／待確認，附上受影響位置與下一步。

客戶回覆不只是禮貌訊息，而是變更決策的紀錄。用同一個 ID 連結批注、修訂位置、QC Finding 和最終回覆。
14｜總結

五個交付習慣

1先建 Log批注、版本、位置、狀態
2再看影響局部、跨章節、跨文件
3鎖定一致性術語、數值、時間點、版本
4AI 做廣度抽取、比對、找矛盾、報告
5人工放行證據、醫學、法規、交付

每一項修訂，都能回答：為何改、改了哪裡、影響什麼、誰確認、如何放行。

PDF：瀏覽器開啟後使用 `?print-pdf` 進行列印版面檢查。

結束時再次強調：良好的 Protocol 修訂工作，是可追溯、可交叉檢查、可由團隊重複執行的品質流程。
